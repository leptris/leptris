# Taurus Architecture

This document describes the architecture of Taurus XML parser.

## Overview

Taurus is a high-performance XML parser and XPath engine implemented in pure C with a two-mode parsing architecture optimized for different use cases.

## Two-Mode Parsing Architecture

Taurus provides two parsing modes with different performance characteristics:

### Copy Mode (taurus_parse_string)

* Creates `ptr_element` structures (72 bytes each)
* Copies input buffer internally
* Uses pool allocation for O(1) allocations
* Best for: General use, when input buffer lifetime is managed externally

### Inplace Mode (taurus_parse_string_inplace)

* Uses `compact_element_v2` storage (16 bytes each)
* Zero-copy parsing with zero-check allocator
* 4.5x smaller memory footprint per element
* Best for: Maximum performance, large documents, streaming scenarios

== Key Components

### DOM Layer (`src/taurus/dom/`)

* `element.c/.h` - Element nodes with attribute hash table (O(1) lookup)
* `text.c/.h` - Text nodes
* `cdata.c/.h` - CDATA sections
* `comment.c/.h` - XML comments
* `pi.c/.h` - Processing instructions
* `doctype.c/.h` - DOCTYPE declarations
* `node.c/.h` - Base node operations
* `compact_accessor.h` - Accessor functions for compact mode
* `ptr_element.h` - Pointer-based element structures (72 bytes)

### XPath Engine (`src/taurus/xpath/`)

* `lexer.c` - Tokenization
* `parser.c` - AST generation
* `evaluator.c` - Navigation and execution
* `evaluator_axes.c` - 13 axes implementation
* `evaluator_operators.c` - 15 operators
* `functions.c` - 27 XPath 1.0 functions

### Parsers (`src/taurus/parse/`)

* `ptr_parser.c` - High-performance pointer-based parser (copy mode)
* SIMD-optimized character scanning (ARM NEON, x86 SSE2)

### Memory Management (`src/taurus/memory/`)

* `pool.c` - O(1) bump-pointer allocation for copy mode
* `zero_check_alloc.h` - Zero-check bump pointer allocator for inplace mode

== Memory Architecture

Taurus uses two different memory allocation strategies:

=== Copy Mode: Pool Allocation

1. **Pool Allocation**: Pre-allocated memory blocks serve all allocations
2. **Bulk Deallocation**: Single pool destroy frees all nodes
3. **String Deduplication**: Hash table for files >= 1KB

=== Inplace Mode: Zero-Check Allocator

1. **Pre-allocation**: 2x input size allocated upfront (no growth needed)
2. **Bump Pointer**: O(1) allocation with no bounds checking
3. **Offset-based**: 4-byte offsets instead of 8-byte pointers
4. **16-byte Elements**: Compact structures for cache efficiency

.Adaptive Pre-allocation Formula

----
// Small files (< 16KB): 2.5x + 1KB safety margin
// Medium files (16KB-256KB): 2x + 4KB safety margin
// Large files (> 256KB): 1.5x + 8KB safety margin
----

== Performance Characteristics

| Operation | Copy Mode | Inplace Mode | Notes
|-----------|-----------|--------------|-------
| Parse (1KB) | 12.62 µs | 5.93 µs | 2.13x faster
| Parse (50KB) | Baseline | 30-50% faster | SIMD optimizations
| Element Size | 72 bytes | 16 bytes | 4.5x smaller
| Memory/Element | ~100 bytes | ~32 bytes | 3x less
| XPath | 1.20x vs libxml2 | Full parity | All features work
| Traversal | 43% faster vs pugixml | Within 5-10% | Similar performance
