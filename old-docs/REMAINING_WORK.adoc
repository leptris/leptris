=== Why Parsing is Still 10x Slower

The optimizations we implemented help with memory efficiency but don't fundamentally change the parsing approach. pugixml's key advantage is:

1. **Single-pass parsing with in-place null termination**
   - pugixml null-terminates ALL strings during parsing
   - Element names, attribute names, attribute values, text content, etc.
   - No post-parse string conversion needed

2. **Our approach requires two passes:**
   - First pass: Parse into StringViews (zero-copy)
   - Second pass: `finalize_strings()` converts StringViews to C strings
   - Even with pool allocation, this is O(n) tree traversal

3. **Limited in-place null termination:**
   - We only null-terminate element names followed by whitespace
   - We null-terminate attribute values (after closing quote)
   - Text content, comments, PIs still need conversion

=== Recommendation

**Accept current parsing performance** as a trade-off for:

- Complete XPath 1.0 support (pugixml has none)
- Cleaner API design with StringView support
- Better namespace handling
- Smaller codebase, better maintainability

For parsing-heavy workloads, users should consider using pugixml directly.

== Phase C Implementation Notes

The in-place null termination implementation includes:

1. **Element name null-termination** (`parse_name_view`):
   - After parsing element name, check if next char is whitespace
   - If yes, replace with '\0' AND advance position
   - This ensures parsing continues correctly

2. **Attribute value null-termination** (`parse_attribute_value_view`):
   - Replace closing quote with '\0' after finding it
   - Already working since we advance past the quote

3. **StringView checks in getters**:
   - `taurus_element_get_name()` - checks `taurus_sv_is_null_terminated()`
   - `taurus_element_get_prefix()` - checks `taurus_sv_is_null_terminated()`
   - `taurus_element_get_namespace_uri()` - checks `taurus_sv_is_null_terminated()`

4. **Serialization fixes**:
   - Updated `serialize.c` to check StringViews when C strings are NULL
   - Updated C14N serialization to check StringViews
   - Updated `taurus_element_lookup_namespace()` to check StringViews

== Notes

*Why Attribute Access is at parity:*
- The public API functions are non-inline
- pugixml uses C++ methods that can be inlined by the compiler
- Acceptable performance (within 15%)

*Why Parsing wasn't fully optimized:*
- Requires fundamental rewrite to match pugixml's approach
- Would need aggressive in-place null termination for ALL strings
- Risk of breaking edge cases
- Not worth the effort for current use cases
